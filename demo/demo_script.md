```bash

cd backend

cd frontend
npm run dev

# Terminal 3 — ngrok (optional, for reviewer phone access)
ngrok http 8000

# Terminal 4 — ready to run seeder
# (don't run yet — fire it during Scene 3)
```

- Tab 1: `http://localhost:5173`           → Dashboard
- Tab 2: `http://localhost:5173/map`       → Map View

## Scene 5 — Duplicate Detection & Human Verification (2 minutes)

**[Switch back to Dashboard]**

> "Scroll down — find the ticket labelled FLAGGED in amber.
> That's ticket 18: 'NEED WATER SECTOR 3 URGENT PLEASE HELP'.
> Our duplicate-detection layer compared this to ticket 17 —
> same area, nearly identical message — and flagged it automatically."

**[Point to the amber FLAGGED badge]**

> "This is critical because in a crisis, well-meaning people forward the same distress message
> to multiple channels. Without this, the same family could receive three rescue teams
> while another family gets none."

**[Click Verify on the flagged ticket — assuming the verify workflow is built]**

> "The coordinator reviews it and decides: yes, this is a real duplicate, dismiss it.
> Or — if it's a second separate incident that looks similar — verify it as a new request.
> This is what we call Human-in-the-Loop: AI raises the alert, human makes the call."

**[Status changes to VERIFIED — green badge]**

> "The status updates instantly. The classifier never makes the final decision alone."

## Q&A Prep — Likely Reviewer Questions

| Question | Answer |
|----------|--------|
| "What if the classifier misclassifies?" | The coordinator sees category and urgency on every card and can override. Flagged tickets require explicit verification. |
| "How does the duplicate check work?" | We compute cosine similarity between TF-IDF vectors of new and existing ticket texts. If similarity > threshold (e.g. 0.75) from the same geographic area, the ticket is flagged. |
| "What database are you using?" | SQLite for the demo. The schema is identical for PostgreSQL + PostGIS — swap `DATABASE_URL` env variable. |
| "Can it handle real SMS?" | Yes — replacing `POST /simulate/sms` with a Twilio/MSG91 webhook requires zero changes to the rest of the stack. |
| "What's next?" | Volunteer PWA (offline sync), Telegram alerts, PostgreSQL + PostGIS geo-queries, LLM classifier upgrade. |
| "Why FastAPI over Django?" | Async by default, auto-generates OpenAPI docs, keeps AI/backend in one Python codebase — no context switch. |
